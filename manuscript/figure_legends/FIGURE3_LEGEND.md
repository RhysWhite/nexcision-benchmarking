# Figure 3 legend

**Figure 3. Scalability and resource use of NEXCISION v0.1.0.**

**A,** Elapsed time versus input-matrix size. Each teal circle is one measured execution (five per size); navy horizontal strokes denote the configuration median. The charcoal dashed line is the log–log power-law fit to configuration medians for inputs of approximately 100 MB or larger (exponent 0.978). The smallest ~10 MB input is shown but excluded from that fit because sub-second startup variability was comparatively high. The original-scale linear regression reported in the Results is a separate model and is not overlaid because it predicts a nonpositive runtime at the smallest input. Both axes are logarithmic.

**B,** Peak resident set size (RSS) versus input size. Teal circles show five measured executions per size, navy horizontal strokes indicate medians, and the charcoal dashed line is the original-scale linear regression fitted to configuration medians (slope 4.849 GiB RSS per GiB input). Both axes are logarithmic. Panels A and B show different measurements from the *same* 30 executions.

**C,** Association between matrix shape and runtime at broadly similar input size. Individual executions (five per matrix design) are shown as navy circles (tall), teal squares (balanced), and amber triangles (wide); black horizontal bars mark medians. The y-axis starts at zero. Labels give taxon count × site-row count and actual input size. The three designs varied both taxa and site-row counts, so this comparison does not isolate the effect of site-row count independently.

**D,** Elapsed time versus number of supplied intervals for the same approximately 0.965 GiB input matrix. Teal circles are individual executions (five per interval count); the navy line connects configuration medians. The x-axis is logarithmic and the y-axis begins at zero. Median runtime increased by 13.5% between 1 and 100,000 intervals.

Five measurements are shown for every plotted configuration. Small, deterministic horizontal offsets separate overlapping points for legibility; these offsets affect only display positions, not actual input sizes, interval counts, medians, or fitted models. Marker shapes, luminance, line styles and labels permit interpretation without colour. A total of 105 observations are shown across panels A–D, corresponding to 75 distinct executions because Panels A and B share the same 30 measurements. The full Experiment 2 archive contains 105 measured executions across 21 configurations; geometry and provenance comparisons appear separately in Figure S2.

All benchmark measurements used the frozen v0.1.0 wheel on one pinned logical CPU of an exclusively allocated AMD EPYC 9374F Linux node with node-local XFS storage. Each configuration had one unreported warm-up and five randomized measured repetitions; page cache was not cleared. Benchmark correctness flags covered exit status, expected row counts, declared dimensions and output presence; full nucleotide-content comparison was evaluated separately in Experiment 1. These are archived v0.1.0 data, not new measurements from a later software release.
